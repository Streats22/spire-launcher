Roadmap

Spire stays a local-first Hytale instance launcher — Prism-style profiles, content you control, no Spire account. This page is how we prioritize work. Dates are soft; order is intentional.

Principles Now Next Later Exploring Not building Feedback

Principles

  • Local-first Profiles, keys, and tokens stay on your machine. Optional update checks stay anonymous and off-switchable.
  • You own the game Spire never redistributes Hytale. Official auth and installs only.
  • Instances are the product Isolation, packs, and per-profile content beat a single global mods folder.
  • Ship trust before novelty Signing, updates, and clear account/install UX land before speculative extras.

Now

In progress / soon

Finish the 0.2 line so installs feel trustworthy and daily mod workflows feel complete.

  • Reliable in-app updates Every Release ships latest.yml / blockmaps so Setup builds can update without hunting GitHub.
  • First-run clarity Obvious path: Accounts → client → create instance → mods. Fewer “where do I sign in?” dead ends.
  • Mod update workflow See what’s outdated, update one or all, and show Installed / Update on browse + detail pages.
  • Instance identity Preset + custom icons on home cards (and keep expanding the preset set).
  • Release hygiene Keep updates/latest.json, release notes, and Pages docs aligned with what users actually download.

Next

Upcoming

After the current line feels solid for most players.

  • Code signing Windows SmartScreen and macOS Gatekeeper trust — fewer “damaged app” / protected-PC scares.
  • Onboarding checklist Lightweight first-launch tips that disappear once Accounts + client + an instance exist.
  • Content browser polish Faster search, clearer source status, better empty states when APIs or keys are missing.
  • Packs UX Clearer export/import of .spirepack, including icons and “what’s inside” before you import.
  • Linux / macOS install friction Docs + in-app copy for AppImage permissions, quarantine, and common install paths.

Later

On the horizon
  • Deeper dependency handling Smarter required-mod graphs across more stores, with conflict warnings when sources allow.
  • Servers & multiplayer helpers Richer server list tools and join flows without turning Spire into a social network.
  • UI localization Ship Spire’s own interface in more languages (game translations already install as content).
  • Modrinth when Hytale lands Plumbing is ready; turn it on when the catalog exists.
  • Accessibility pass Keyboard, contrast, and screen-reader polish across main + Manage windows.

Exploring

Maybe

Ideas under consideration — not commitments.

  • Shared pack discovery A curated index of community .spirepack links — still downloaded and kept local.
  • Instance templates One-click “modded survival / creative / vanilla-ish” starters without locking you in.
  • Performance tooling Simple launch diagnostics (Java args presets, log tips) for common crash patterns.

Not building

Out of scope
  • Spire accounts / cloud sync Conflicts with local-first. Backups stay packs + your own files.
  • Redistributing Hytale No cracked clients, no bundling the game in the installer.
  • Forced telemetry No analytics SDK. Update checks remain optional and anonymous.

Feedback

Priorities shift with Hytale’s ecosystem and what people actually hit day to day. Open an issue or discussion on GitHub — especially if something on Now is broken for you.
